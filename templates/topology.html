    Provider hints for the L3 views (optional) One rule per line: what = type provider.       Preview only. vPC view: each vPC pair is one frame and each bundle spanning the pair is one line (vPC id, member count, rated speed). Physical view: every cable.       Which captures would add the most to the picture, best first. New capture: a device its neighbors see but nobody captured; its capture confirms the one-sided links, names its ports and shows the neighbors only it can see. Capture again: a captured device whose capture has no CDP / LLDP neighbor table. Ranked by links that a neighbor table reports at the device (links only inferred from ARP, descriptions or routes count after those), then different captured neighbors, then MAC addresses behind it. Collect list is the file to run on the device.

      What to upload

      One capture per device is enough. Each capture should contain these commands (Cisco names shown; the Switch Analyzer collect lists already include most of them):

      • show cdp neighbors detail and show lldp neighbors detail - the links.
      • show etherchannel summary / show port-channel summary and show vpc - bundles and vPC pairs.
      • show inventory and show version - model, serial number and stack members.
      • show mac address-table and show ip arp - end hosts (optional).
      • show ip interface brief or the running configuration - management IP address.

      F5 BIG-IP: upload the .ucs archive (System > Archives > Create, or tmsh save sys ucs name). It holds the configuration only; add a tmsh capture of the same unit with show net interface and show net arp for port state, speed and ARP. A capture of show commands alone (no UCS) is drawn as well, without self IPs and routes (F5 documentation: archives).

      The builder matches the two ends of each link by serial number, management IP and hostname, so a device that appears in a neighbor table is placed on the diagram even when you did not capture it (grey box).
