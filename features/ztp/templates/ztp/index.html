ZTP Syslog Receiver

Stopped.

Receives ZTP process log lines the switch forwards during provisioning (see the "Live Log Target" field on the Setup tab) and feeds them into the Activity Log tab. Port 514 is the syslog default and needs root/administrator privileges to bind, same as the DHCP server — use a high port (e.g. 5140) here instead if that's not available, as long as the switch side can be pointed at the same port. Optional — start it if you want live process visibility, but the DHCP/SFTP servers work fine without it.

ZTP DHCP Server

Stopped.

This is the most dangerous control on this page. A DHCP server that answers on the wrong interface becomes a rogue DHCP server and can hand out leases to production devices. Only point this at a NIC that is on an isolated staging segment — never your production LAN. Requires dnsmasq to be installed on this host, and root/ administrator privileges to bind UDP/67 (this tries sudo -n automatically if Keystone itself isn't running as root — run sudo -v in the same terminal before clicking Start so that can succeed without a password prompt, which has nowhere to go from here). This is the last thing the switch actually needs before it can boot into ZTP, so start it last — once SFTP (and, optionally, Syslog) are already up.

Only interfaces with an IPv4 address are listed. Pick the one physically connected to the staging switch — never your main LAN/Wi-Fi adapter.

dnsmasq lease duration (e.g. 15m, 30m, 1h). Kept short by default for ZTP staging -- devices only need this address for a few minutes before rebooting into their static config, so a short lease frees the pool quickly for the next unit. Only matters for devices without a MAC filled in below (those get a pinned reservation instead and ignore this).

Same host/port/credentials as the SFTP server tab, plus /ztp_script.ini. Max 127 characters — the switch reads this from a fixed-size DHCP field, and anything longer is silently truncated on the wire (a shorter password or an IP instead of a hostname both help).
